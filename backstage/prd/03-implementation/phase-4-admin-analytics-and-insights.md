# Phase 4: Admin Analytics and Insights

## Scope Boundary For This Phase

Phase 4 builds the admin analytics dashboard and insight agents for recent
athlete queries. It does not create document-edit automation, report exports,
or integrations that act in external athletic systems.

Admin conversational agent responses must use the same async stream bridge as
athlete chat: the admin question API persists the admin turn, creates an
assistant placeholder, dispatches a Celery task, and returns `task_id` plus
stream metadata. The worker executes the admin chat agent and publishes ordered
chunks, progress, completion, and error events to Valkey Streams, with pub/sub
notification for the HTTP stream endpoint. Long-running non-conversational jobs
in this phase, such as dashboard insight runs, remain polled by `run_id`.

## Definition of Done

- [x] Admin dashboard shows query volume, topics, unanswered questions, and NIL/compliance/recruiting risk.
- [x] Admin Query review renders anonymized backend rows with topic/risk filters and safe expandable detail fields only.
- [x] Athlete identity is anonymized in backend analytics payloads.
- [x] Nightly and manual dashboard insight runs work through polled `run_id` status on the backend.
- [x] Admin chat side panel answers analytics questions from authorized data, streams agent output by `task_id`, and persists admin session history.
- [x] Manual insight triggers are audited; admin chat submissions and privacy-safe runtime trace behavior are covered.
- [x] No export/report feature is included in MVP.

## Local Dashboard Validation

Use the local validation script from the backend workspace:

```bash
DEBUG=true ENVIRONMENT=local uv run python scripts/phase4_dashboard_seed.py --poll
```

The script seeds deterministic Phase 1 dev users, deletes only prior seeded-athlete conversations whose title starts with `[phase4-demo]`, inserts synthetic NIL, compliance, recruiting, process, unsupported, and unanswered turns, then triggers a manual 7d dashboard insight run through `DashboardInsightService`. Optional flags include `--seed-only`, `--trigger-run`, `--poll`, `--no-poll`, `--skip-seed`, and `--window 7d|30d`.

Local validation on July 1, 2026 seeded 12 synthetic turns, confirmed `/api/v1/admin/analytics/summary?window=7d` and `/api/v1/admin/analytics/queries?window=7d&limit=11&offset=0` returned data, and confirmed repeatable topic/risk filters returned matching rows. The triggered run `5cb307c0-5c82-4d06-86ab-1418c351741b` moved from `pending` to `processing` and then `failed` with sanitized error `BadRequestError`; `/admin/dashboard-insights/current?window=7d` returned 404 because no completed output was produced. This is treated as a provider/config validation failure rather than an analytics wiring failure, and the seeded analytics data remains valid for dashboard summary and Query review validation.

Follow-up validation on July 1, 2026 fixed admin chat requests that looped on
`analytics.summary` by making that value a supported metric-tool input and by
persisting a safe unsupported response if the admin-chat loop guard still trips.
Runtime tracing now uses the documented `LANGFUSE_BASE_URL` setting as the only
Langfuse URL configuration.
