# Data Model

> Generic data model spec. Defines entities, relationships, and constraints.
> The `Example` entity is illustrative — replace it with your domain model. See
> `docs/architecture/db.md` for the implementation conventions.

## Conventions

- UUID primary keys, server-generated (`gen_random_uuid()`).
- `created_at` / `updated_at` as `TIMESTAMPTZ` with server defaults.
- Foreign keys declare `ondelete` explicitly.
- JSONB for flexible/structured payloads.
- SQLAlchemy 2.0 async models; Alembic migrations for every change.

## Entities

### User

Managed by `fastapi-users`.

| Field | Type | Constraints |
|-------|------|-------------|
| id | UUID | PK |
| email | string | unique, required |
| hashed_password | string | required |
| is_active | bool | default true |
| is_superuser | bool | default false |
| is_verified | bool | default false |

### Example

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | UUID | PK | server-generated |
| owner_id | UUID | FK → User, `ondelete=CASCADE`, indexed | who owns it |
| name | string(255) | required | display name |
| description | text | optional | longer text |
| status | string(50) | default `draft` | `draft` / `active` / `archived` |
| data | JSONB | default `{}` | flexible payload (e.g. agent-generated content) |
| created_at | timestamptz | server default | |
| updated_at | timestamptz | server default, on update | |

## Relationships

```
User 1 ──── N Example      (Example.owner_id → User.id, CASCADE on delete)
```

## Status Lifecycle (Example)

```
draft ──► active ──► archived
  ▲                     │
  └─────────────────────┘  (un-archive returns to active)
```

## Validation Rules

- `name` is required and trimmed; max length 255.
- `status` must be one of the allowed values.
- `owner_id` must reference an existing, active user.
- `data` must be a JSON object (not an array or scalar).

## Indexes

| Index | Columns | Purpose |
|-------|---------|---------|
| `ix_examples_owner_id` | `owner_id` | List a user's examples efficiently |
| `ix_examples_owner_status` | `owner_id, status` | Filter a user's examples by status |

## Migrations

Every schema change ships as an Alembic revision. Review autogenerated
migrations before committing (server defaults and JSONB index types are often
missed by autogenerate).
