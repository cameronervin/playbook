# Phase 2: Athlete AI Experience

## Scope Boundary For This Phase

Phase 2 builds the core athlete-facing AI loop: persisted conversation history,
message submission, streamed assistant responses, grounded KB retrieval,
citations, conversation-scoped file context, and safety/refusal behavior.

Streaming must use an async worker handoff: the message submit API persists the
user turn, creates an assistant placeholder, dispatches a Celery task to execute
the athlete chat agent, and returns a `task_id` plus stream metadata. The Celery
worker runs the LangGraph agent and publishes ordered chunks, progress,
completion, and error events to Valkey Streams, with a pub/sub notification path
for the HTTP stream endpoint. The stream endpoint validates the athlete's
conversation/message ownership and subscribes to the Valkey stream/channel for
the returned `task_id`.

## Definition of Done

- [ ] Athletes can create, revisit, and continue conversations.
- [ ] User messages submit through the API, enqueue a Celery agent task, return `task_id`, and assistant responses stream from Valkey Streams/pub-sub before persisting correctly.
- [ ] Grounded answers include citations tied to retrieved KB chunks.
- [ ] Unsupported and sensitive prompts decline safely.
- [ ] Conversation file uploads work without adding files to the shared KB.
- [ ] Athlete chat UI handles loading, streaming, citations, errors, and responsive layouts.
- [ ] Phase 2 tests and relevant eval smoke checks pass.
